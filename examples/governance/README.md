# governance

A DAO / governance voting contract for Soroban, generated by
[soroban-forge](https://github.com/soroban-forge-labs/soroban-forge) from the
`governance` template.

## Features

- **add_member / remove_member** — the admin manages who can vote
- **create_proposal** — any member can open a new proposal
- **cast_vote** — one member, one vote, with double-vote prevention
- **execute_proposal** — executes after the voting period ends, if quorum is
  met and votes-for exceed votes-against
- Configurable quorum and voting period set at initialization

## Where voting power comes from

Voting power is never supplied by the caller. `cast_vote(voter, proposal_id,
in_favour)` has no weight argument: every eligible vote counts exactly
`VOTE_WEIGHT` (1), so one voter cannot outvote everyone else, and negative or
inflated votes are impossible by construction.

A voter is eligible when they are a **member** registered by the admin
(`add_member`) **at or before the ledger the proposal was created in**. This
snapshot means members added while a vote is open cannot swing it, and
generating fresh addresses (a sybil attack) gives no voting power. Removing a
member stops them voting from then on; votes already cast still count.

`quorum` is therefore a number of members.

### Token-weighted voting

To weight votes by token holdings, replace `voting_power` in `src/lib.rs` with
a balance read through `token::Client`. Do not read the *current* balance at
vote time: the same tokens could be transferred between accounts and voted
with repeatedly. Snapshot balances when the proposal is created (for example
with a token that records historical balances, or by locking tokens in this
contract for the voting period).

## Develop

```sh
cargo test                 # run unit tests
stellar contract build     # build the deployable wasm
```

## Deploy to testnet

```sh
stellar contract deploy \
  --wasm target/wasm32v1-none/release/governance.wasm \
  --source-account <your-identity> \
  --network testnet
```

See the [Stellar docs](https://developers.stellar.org/docs/build/smart-contracts)
for the full workflow.

## Security

This template is a starting point, not audited code. See [security-considerations.md](https://github.com/soroban-forge-labs/soroban-forge/blob/main/docs/security-considerations.md) for what it does and does not protect against.
